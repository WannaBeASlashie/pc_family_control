# 离线额度设计（FR-17）

> 状态：**✅ 已实现（v2.0，commit 待填）** ｜ 设计定稿：2026-10-20
> 决策记录：缓存范围为**全部启用账户**（用户确认，账户数量少）；其余按原设计落地。
> 与原设计的实现偏差见 §15。

---

## 1. 目标与非目标

**目标**
1. 服务器短暂不可达（重启/网络抖动/维护）时，孩子仍可**上机**，不受影响
2. 离线用量**必须被记账**：重连后自动补账，计入余额、每日额度、滑动窗口
3. 拔网线**无利可图**：离线可用时长有硬上限，且这些时长照样扣费

**非目标**
- 离线期间执行完整策略（时段/每日/滑动）——只执行简化的"离线额度"，重连后由历史会话自然补算
- 离线审批/申请加时——离线没有家长通道，按钮禁用
- 防住拥有管理员权限的攻击者——缓存文件的完整性依赖"孩子是标准用户"这一既有前提

## 2. 现状与差距分析

先澄清一个重要事实——**有一半场景现在已经是对的**：

| 场景 | 现状 | 结论 |
|---|---|---|
| 上机中服务器断开，之后恢复 | 心跳恢复后按 `startedAt` 补结算，中断期间**照常扣费** | ✅ 已正确，无需离线逻辑 |
| 上机中服务器断开，余额耗尽 | Agent 不再收到 lock 指令，孩子继续玩到恢复 | ❌ 缺口 A：离线无强制手段 |
| 服务器断开期间**新上机** | 登录请求失败，"服务器无响应" | ❌ 缺口 B：可用性问题 |
| 断开期间余额/倒计时显示 | 冻结在最后心跳值 | ❌ 缺口 C：显示失真 |

本设计解决 A/B/C 三个缺口。

## 3. 威胁模型

| 攻击 | 对策 | 残余风险 |
|---|---|---|
| 拔网线换取无限时长 | 离线额度硬上限（人/天 + 机/天）+ 重连补账 | 上限内的时长照样扣费，无净收益 |
| 改本机时钟（回拨重领额度） | 离线额度按本地日期记账；台账含 lastSync 时间戳 | 回到"昨天"可多骗一天额度，**有界**（见 §11） |
| 读取/篡改/删除本地缓存 | 缓存与台账仅 SYSTEM/管理员可读写（显式 ACL），孩子是标准用户 | 拿到管理员权限则整个体系失效（既有前提） |
| 离线登录他人卡号 | 缓存内含 PIN 哈希，本地校验与服务器同算法 | 与在线同一强度 |
| 断网时禁用账户/改了额度 | 缓存是快照，无法感知 | 可用旧额度上机（≤上限），重连后记账并审计 |

**核心原则：离线是有界信任（bounded trust）。** 任何离线攻击的最大收益 = 当日离线额度上限，且全部计入账本。

## 4. 总体方案

```
在线（现状 + 增强）：
  Server ──心跳──▶ Agent
            │
            └─携带 offlineKit（人员离线档案快照）
                 Agent 持久化到受保护缓存文件

离线（新增）：
  心跳连续失败 ≥2 次（约 20s）→ Agent 进入离线模式
    ├─ UI：锁屏显示「离线模式（受限）」
    ├─ 登录：本地校验 PIN → 本地额度判断 → 放行，建本地会话
    ├─ 计时：本地时钟倒计时（min(快照余额, 离线额度)）
    ├─ 耗尽：本地锁屏 → 宽限 → 本地 WTS 注销（与在线同 UX）
    └─ 全部写入本地台账（JSONL，追加式，带唯一记录 ID）

重连（新增）：
  心跳成功 → 先在 Gate 内执行 sync-offline：
    ├─ 已结束的离线会话 → 服务器按历史时间建会话行 + 补扣费
    ├─ 进行中的离线会话 → 服务器按真实开始时间补建 active 会话，无缝接管计费
    └─ 幂等：按记录 ID 去重
  然后 Agent 回到在线模式，清空本地台账
```

## 5. 数据流细节

### 5.1 offlineKit（心跳响应新增字段）

仅包含**在这台机器成功登录过的人员**（首次登录时由服务器下发入 kit，自然收敛到"谁常用这台机器"）：

```json
"offlineKit": {
  "version": "2026-10-20T12:00:00Z",
  "tzOffsetHours": 8,
  "persons": [
    { "cardNo": "001", "pinHash": "盐:哈希", "balance": 1800, "quota": 1800 }
  ]
}
```

- `balance`：最近一次心跳的**有效余额**（策略计算后的值）
- `quota`：该人员的离线额度（策略覆盖值或全局默认，秒）
- kit 很小（每人约 200B），每次心跳都携带，不做增量优化（局域网流量可忽略）
- **kit 有效期 72h**：超过则离线登录不可用（防止拿着陈年快照反复用）

### 5.2 Agent 离线状态机

```
Online ──心跳连续失败≥2──▶ Offline
  ▲                          │
  └────心跳成功─── 等待 sync-offline 完成 ────┘
```

- 进入离线不结束在线会话（若有）：继续本地倒计时
- 离线登录条件：kit 未过期 && PIN 校验通过 && 个人当日离线剩余 > 0 && 机器当日离线剩余 > 0
- 离线额度记账（本地台账）：`{日期, cardNo, 已用秒}` —— 按本地日期（kit 带 tz）

### 5.3 本地台账（JSONL，追加式）

```json
{"id":"a3f...-guid","cardNo":"001","type":"offline_login","ts":"..."}
{"id":"b7e...-guid","cardNo":"001","type":"offline_logout","ts":"...","charged":1234}
{"id":"c1d...-guid","cardNo":"001","type":"offline_exhausted","ts":"...","charged":1830}
```

- 每条带 GUID，重连上报后标记 `synced`（或移入已同步文件）
- 单会话聚合成一条上报记录：`{recordId, cardNo, startedAtUtc, endedAtUtc, chargedSeconds, endReason}`

### 5.4 重连补账（新端点 `POST /api/client/sync-offline`）

```json
{
  "completed": [ {"recordId":"guid","cardNo":"001","startedAtUtc":"...","endedAtUtc":"...","charged":1234,"endReason":"logout"} ],
  "active":    {"recordId":"guid","cardNo":"001","startedAtUtc":"..."}
}
```

服务器处理（在机器 HMAC 认证下）：

1. **去重**：`sessions.ClientRecordId` 唯一索引，重复上报跳过
2. **已完成会话**：插入 ended 会话行（真实起止时间）→ `balance -= charged`（钳到 0）→ 流水 `offline_charge` → 审计
3. **进行中会话**：插入 active 会话行（`StartedAt = 上报的开始时间`），之后心跳的常规结算自然接管——**每日额度/滑动窗口自动把离线时段计入**（PolicyEngine 按会话行与窗口的重叠计算，天然支持历史会话）
4. **防篡改钳制**：单条 charged 上限 = 该人员离线额度 × 1.5（宽限余量）；startedAt 早于 48h 前的钳到重连时刻——时钟回拨攻击的收益被压到有界
5. 响应返回接管后的会话与有效余额，Agent 切回在线显示

## 6. 本地缓存与安全

| 项 | 方案 |
|---|---|
| 位置 | `C:\ProgramData\HomeCtrl\offline\`（kit.json + ledger.jsonl） |
| ACL | 安装脚本设置：仅 SYSTEM 与 Administrators 完全控制，Users 无权限（`icacls /inheritance:r`） |
| 完整性 | 台账追加式 + 记录 GUID；不做签名（威胁模型内篡改需要管理员权限，越界） |
| PIN 哈希 | 与服务器同格式（PBKDF2-SHA256 100k），泄露面等价于局域网明文登录包 |

## 10. 边界情况清单

1. **离线期间服务器其实活着**（仅 Agent 网络故障）：离线登录后重连，会话被补建——若当时策略本应拒绝（如宵禁），审计会留痕；时长有界，接受
2. **离线中 Agent 重启**：台账落盘，重启后读取恢复状态；进行中会话若无 logout 记录，以"重启时刻+心跳宽限"估算结束（或标记 unknown，按开始到重启计费）
3. **重连时人已换**（离线会话 A 未注销，B 离线登录）：单会话约束离线同样生效——A 的会话先在本地结束（logoff 或换人强制下机）才能登 B
4. **补账把余额扣成负数**：钳到 0（与在线耗尽一致）
5. **机器时钟快/慢漂移**（非恶意）：charged 以本机时钟为准，误差自然进入账本；漂移大时触发 §5.4-4 的钳制审计

## 11. 残余风险（明确接受）

| 攻击 | 最大收益 | 为什么接受 |
|---|---|---|
| 时钟回拨到昨天重领离线额度 | 每回拨一天多 N 分钟（N=离线额度） | 操作复杂（改系统时间+拔网线），收益微小，且台账有痕迹 |
| 拔线—重连反复套利 | 0（每次离线用量都补账扣费） | 设计目标即此 |
| 离线期间家长停用账户 | 旧快照额度内可上机 | ≤ 每日上限，重连即失效 |

一句话：**孩子折腾半天，最多多玩"离线额度"那么久，且全部计费**——比跑去找家长要 15 分钟还费劲。

## 12. 测试计划

1. 起 Agent → 心跳拿到 kit → 断言缓存文件生成且 ACL 正确

## 15. 实现偏差与补充（落地时确定）

1. **缓存范围**：全部启用账户（决策点 2 用户选择），kit 每人心跳全量携带（局域网流量可忽略）
2. **本地台账**：快照 JSON（`ledger.json`）而非追加式 JSONL；每 60s 刷新 `LastAliveUtc`，Agent 重启时活动会话按"最后活跃+60s"估算结束转为待补账
3. **ACL**：由 `install-client.ps1` 用 `icacls` 设置（SYSTEM/管理员全控、Users 无权限），Agent 代码不引 Windows 专有包
4. **收养会话**（服务器断开时已在机的在线会话）离线耗尽时仅本地锁屏，不强注本机——logoff 由服务器恢复后的正常耗尽流程处理；若离线中主动下机则打标，重连后向服务器补 logout
5. **sync-offline 响应即标准心跳负载**：补账后直接应用，避免重连时的状态闪动
6. **HttpClient 禁用系统代理**：受控机局域网直连，且离线判定依赖连接拒绝的快速失败（Clash 类代理会拖慢失败检测——实测踩坑）
7. 离线模式进入耗时 ≈ 2 个心跳周期（10s 间隔约 20s）；期间登录按在线路径处理（显示"服务器无响应"）
